# Stage 4 — First run: free ingest, then the user's switch-on decision

## First ingest (free, no model calls)

```sh
python3 bin/cli.py --ingest-only --max-messages 0
```

A brand-new `data/fragments.db` is created from `config/schema.sql` automatically.

**Checkpoint:**

```sh
sqlite3 data/fragments.db "PRAGMA user_version;
  SELECT (SELECT COUNT(*) FROM messages), (SELECT COUNT(*) FROM turns);"
```

user_version is `7`; both counts are > 0 (assuming the project dirs contain history). Zero counts with existing `.jsonl` files means `project_dir` is wrong — go back to configure.md.

## Room files

For each `room_dir`, create `todo.md` with a front page (the engine never writes this file; it belongs to the user's agent):

```markdown
# todo

> Working memory for things that must survive the session but aren't yet "memory".
> The pipeline does NOT read or write this file — your agent maintains it by hand.

- [ ] …
```

`context-last-24.md`, `digest.md`, `constants.md` will be generated by the engine — do **not** create them by hand.

## Switching memory on (the user's call)

Everything is now wired but **off**. Tell the user, in your own words:

- Turning on **card generation** processes **yesterday only** as its first act (a handful of model calls — roughly one per ~14 conversation rounds), then cards new conversations automatically as they cross the thresholds.
- Turning on the **night curator** adds at most one agentic call per enabled room per night, skipped when there are no fresh cards.
- Deeper history **backfill** exists but is a separate conversation: if they ever want it, estimate the token cost from the actual session count first and get an explicit yes before running anything.

If the user turns on cards: set `watcher.auto_cards: true`, then run yesterday:

```sh
python3 bin/cli.py --process-yesterday
```

(Provider and model come from `settings.model_access` / `settings.card_gen` — nothing to pass here.)

**Checkpoint:** `sqlite3 data/fragments.db "SELECT COUNT(*) FROM cards;"` > 0. **Do not paste cards at the user** — after the index step below, tell them yesterday now lives in `room_dir/context-last-24.md` and they can look whenever they like.

If the user turns on the night curator: set `midlayer.enabled: true` (its real run happens inside the nightly job — no call now).

If they keep everything off: also fine. Ingest keeps accumulating for free; note in your final report how to enable later (this section's switch names).

## Index and context (once cards exist)

```sh
python3 bin/cli.py --rebuild-index
python3 bin/cli.py --rebuild-context
```

(With yesterday-only data the tree will be shallow — clustering gets interesting past ~50 cards. Say so, so the user doesn't judge the tree on day one.)

**Checkpoint:** `sqlite3 data/fragments.db "SELECT COUNT(*) FROM clusters;"` > 0, and each `room_dir/context-last-24.md` exists and contains yesterday's cards.

## Night curator dry-run (only if `midlayer.enabled`)

Dry-run first (free):

```sh
python3 bin/cli.py --curate-dry-run
```

**Checkpoint:** prints a tree-change report per enabled room, no traceback. The real `--curate` runs inside the nightly job (scheduling.md). Don't run it now unless the user asks — the first night proves it.
