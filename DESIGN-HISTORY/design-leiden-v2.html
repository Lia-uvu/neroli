Event Memory Pipeline: Leiden Index

v1 searched for structure directly in embedding space through several generations of threshold and centroid experiments. v2 changed the representation: Cards remained the durable memory layer, while a rebuildable entity graph became the index. A Midlayer then projected that hierarchy into bounded working context.

1. Storage is not the index

v1 used the event Card both as the returned memory and as the direct input to clustering. That quietly restricted the available structure to Card embeddings and raw tags. Cards had no native edges, so every connection had to be guessed from compressed continuous distance.

  • Storage layer: narrative Cards returned to recall, carrying time, provenance, shared/private text, and room ownership.
  • Index layer: canonical entities, graph edges, and communities used only to organize and locate Cards.
Principle

The index is a product of the Cards, never the reverse. If the index fails, it can be rebuilt. Narrative, visibility, provenance, and timestamps cannot be reconstructed after loss and therefore remain on the Card.

Why not use a triple store as both memory and index?

A triple store must split an event into edges so graph algorithms can consume it. That works well for general knowledge, but here the event's causal and temporal context was often the valuable part. Visibility also attached naturally to the whole Card. An edge whose cause was private and consequence was shared had no honest single visibility label. Neroli borrowed graph indexing ideas without making triples the source of truth.

2. Three-layer architecture

STORAGE INDEX raw turns canonical entities -> Card generation -> weighted Card graph -> narrative Cards -> recursive Leiden tree time / room / visibility -> primary + secondary membership | | +----------- retrieval ------------+ MIDLAYER tree snapshot -> fresh-Card report -> viewer-filtered curator workbench -> digest + long-lived constants

The Card generation path was intentionally left intact. v2 changed the index in the middle and added a bounded context layer downstream. This kept one major experiment from requiring a migration of the durable memory layer.

3. Entity layer and conservative deduplication

The v1 Card tags were a useful extraction draft but a poor graph vocabulary. Thousands of tags included many one-off phrases and dozens of variations for the same project or concept. The resulting co-occurrence matrix was too sparse to reveal structure.

  1. Embed a new recurring tag and retrieve a small set of similar canonical-entity candidates.
  2. If candidates exist, ask a small reasoning model whether the tag names the same entity as one candidate or should remain distinct.
  3. Cache the verdict. If no plausible candidate exists, create a new canonical entity directly.
Why two stages?

A synonym dictionary systematically missed project-specific and domain-specific language. Bare-tag embedding merged “same entity” with “related concept.” Embedding was useful for candidate generation; the final merge required a conservative identity judgment. False merges were treated as more damaging than false splits.

The mapping was persisted but reconstructible. Cards and raw tags remained unchanged, making entity resolution an index operation rather than an irreversible rewrite of memory.

4. Weighted Card graph

Every Card became a node. The candidate edge set was the union of two signals:

  • Embedding k-nearest neighbors: a semantic backbone over mean-centered Card embeddings. It supplied edges when related Cards shared no exact entity.
  • Canonical-entity co-occurrence: a discrete topic signal weighted toward rare entities, with generic or corpus-wide entities excluded.

Embedding kept the graph connected; entities sharpened topic boundaries. Neither was reliable alone. A pure semantic graph recreated broad conversational cones. A pure entity graph disconnected related Cards whenever extraction vocabulary changed.

Signal normalization

Embedding similarity and entity co-occurrence occupied different scales. The implementation normalized both over the candidate edge set before combining them. The exact weights were deployment settings; the architectural point was that the community algorithm consumed one weighted graph rather than hard-coding two unrelated decision paths.

5. Adaptive recursive Leiden

Leiden operated on connection patterns rather than one global vector-distance threshold. Compared with label propagation, it offered an interpretable resolution control; compared with Louvain, it guaranteed connected communities.

Why recurse?

Different regions required different granularity. A coherent project history might remain one broad community, while a dense region of everyday topics contained several genuine subtopics. Global depth or size was a poor proxy for internal structure.

run Leiden on the full graph -> top-level communities -> run Leiden on each induced subgraph -> accept a local split only if it beats the null model -> recurse until local structure is no longer significant

Degree-preserving null model

For each proposed subgraph split, the implementation measured observed modularity, repeatedly rewired the subgraph while preserving node degrees, and measured modularity on those random counterparts. A split survived only when its observed score exceeded the null distribution by a configured z margin.

Q_observed > mean(Q_null) + Z × std(Q_null)
The honest knob

No community algorithm is truly free of prior choices. v2 kept one global judgment—how much stronger than randomized structure a split must be—while letting every region determine its own resulting depth. This was more stable and interpretable than tuning a distance threshold for each density regime.

6. Hard backbone, soft coverage

Recursive Leiden naturally produced a hard partition. Neroli used it as the navigation backbone: every Card had exactly one primary leaf. A separate pass asked whether a meaningful share of the Card's edge affinity pointed into another leaf; if so, it received a bounded secondary membership.

This preserved a tree that could be browsed and summarized while allowing one coherent event to remain discoverable from multiple topics. Native overlapping-community algorithms were considered, but their additional complexity was not justified for the first graph implementation.

7. Retrieval remained plural

The graph did not replace existing retrieval paths. The v2 system retained:

  • FTS keyword search and tag matches;
  • time-range browsing across all topics;
  • community-to-subcommunity-to-Card drill-down;
  • Card timelines and full Card detail;
  • source-text fallback when derived representations missed.

Graph traversal from entity to neighboring Cards was identified as a possible future interface, not assumed to be the correct primary retrieval mode. Time remained an ordering and slicing axis rather than a community edge.

8. Midlayer: turning the tree into bounded context

The long-term graph solved organization, but agents still needed a compact view between a one-day ledger and explicit deep retrieval. The Midlayer took nightly tree snapshots, compared their leaves, and gave a curator agent a constrained workspace from which to produce a digest and long-lived facts.

Tree identity through membership

Community IDs could drift after every rebuild. Leaves were therefore matched across nights through containment of stable primary Card membership. Containment tolerated growth better than Jaccard: an old leaf could gain many new Cards without losing its historical identity.

Topology could not define news

The first report rendered new, continued, merged, and split communities directly. Real runs showed that Leiden movement could make old material appear as a new leaf. The clustering topology had no authority to claim that a new real-world event occurred.

Correction after production evidence

A report event became “a leaf containing fresh Cards,” where freshness came from Card timestamps. Topology diff was demoted to a continuity annotation explaining which prior leaf the new line most resembled. Old topology movement without new Cards was summarized, not narrated as news.

Viewer-filtered curator workbench

Each curator ran in a separate directory containing a filtered database copy, the tree report, prior generated artifacts where applicable, and bounded recall wrappers. Invisible Cards were absent; private fields on visible foreign Cards were blank. The curator returned structured output for the parent process to validate and commit—it did not write the canonical database directly.

Digest and constants

The digest was a compact status capsule rather than a daily activity report or a list of cluster keywords. Constants captured infrequent facts that remained useful for months and would otherwise disappear from frequency-based context. Both inherited the Card layer's shared/private provenance rather than inventing a second visibility model.

Why constants were not keyword-triggered

Atomic facts contained too little lexical surface for reliable FTS activation: a new phrase could be semantically relevant without sharing a literal term. Because the pool was deliberately small, the initial design preferred bounded standing injection and reserved keyword-triggered recall for richer event Cards.

9. Privacy remained a storage-layer property

The index could use full context to position an owned Card, but every user-facing projection filtered at Card boundaries. Search, context generation, tree reports, and curator exports reused the same visibility rule. A Card visible across workspaces exposed only its shared fields; its private prose and raw source turns remained owner-only.

The workbench was the important strengthening over prompt-only policy. Once the curator gained tools, asking it not to inspect private rows was insufficient. The rows had to be absent from the database it could access.

10. What changed from v1

The v1 bottleneck

  • Cards had no native discrete edges; vector distance had to invent all structure.
  • Raw tags were fragmented, making entity overlap too sparse to help consistently.
  • One global granularity setting could not fit both coherent and heterogeneous regions.
  • Silhouette score could reward singleton-heavy partitions and hide organizational failure.

What survived

  • Event Cards as narrative memory.
  • Rolling freeze/refeed generation.
  • Mean-centered embeddings and entity evidence.
  • Separate topic and time axes.
  • Primary plus bounded secondary membership.
  • FTS, timeline, and source-detail fallbacks.
  • Card-level shared/private visibility.

The real change

v2 did not discard the memory model. It replaced one organization layer: direct vector-space clustering became conservative entity resolution, a weighted Card graph, and recursive community detection. The lesson was that the quality ceiling came from representation and signal, not from searching indefinitely for a better global threshold.

11. Rejected paths

Centroid-relative clustering

It contained several good ideas—mixed signals, relative thresholds, and aggregate comparison—but remained limited by fragmented tags and compressed embedding distances.

Agglomerative clustering

Average linkage changed the algorithm without changing the underlying signal ceiling. Distance thresholds remained unstable.

Silhouette as the sole quality metric

Cards excluded into singletons could make the remaining partition look artificially clean. Modularity against a null model replaced it as the local split test.

Recursive splitting by cluster size

Large coherent communities were split merely for being large, while small heterogeneous groups escaped. Internal structure replaced size as the stop rule.

Adopting a complete knowledge-graph framework

Infrastructure weight was not the decisive issue. The mismatch was the storage model: triples fragmented events and could not naturally carry the same narrative visibility boundary.

Pure tag co-occurrence graph

It sharpened topics but disconnected semantically related Cards with no shared entity. Embedding kNN remained necessary as a backbone.

Nightly report rewritten from topology changes

Community movement generated false news. Fresh Cards became authoritative; topology remained only supporting context.

Constants in an on-demand keyword pool

Short facts had poor lexical recall. The initial design kept a deliberately bounded standing set instead.
