Event Memory Pipeline

Conversations disappear from a context window. Memory does not have to disappear with them. This document records the first Neroli design: what it tried to preserve, how it generated memory, and why its original clustering approach was eventually replaced.

1. Design principles

Use physical intuition for boundaries

The deployment used spatial language: a room represented an agent workspace, a notebook held durable writing, and an alarm represented scheduled work. The metaphor made ownership questions concrete: where does an object belong, and who should be able to encounter it by default?

Remember from an operating context, not as a neutral extractor

The earliest prompt treated the model as a mechanical extraction tool. Its output resembled a meeting record: correct in outline, but poor at noticing which concrete detail or emotional turn would matter later. The replacement framed the task from the remembering agent's operating context: the conversation is about to leave the context window; write what should survive.

What the comparison suggested

In A/B experiments, the operating-context prompt produced more stable first-person recollection, retained causal texture, and omitted more administrative noise. This did not make the model a policy boundary. It changed judgment quality; deterministic code still controlled what material the model could receive.

Natural language all the way down

Card bodies were prose rather than keyword lists. Prose preserved cause, sequence, and tone; it was readable without another decoding layer and behaved more consistently in embedding space than short, context-free labels. Tags remained secondary indexing signals rather than the memory itself.

2. What to remember: event Cards

The basic unit was an event, not a message and not a fixed-size chunk. One Card represented a span that should be recalled as a whole: a decision, an experiment, a routine, a problem, or a short arc of related interaction. The model could split a window only when it contained genuinely independent event lines.

headline: comparing two deployment options and choosing the reversible one
share: information useful across agent workspaces
private: information belonging only to the source workspace
tags: deployment / rollback / decision

Shared and private were relational, not topical

Decision

Shared meant that another agent could know the material without taking ownership of an experience that did not belong to it. Private meant that disclosure would cross the source workspace's relational boundary. When uncertain, generation chose private.

This distinction was intentionally different from “sensitive versus ordinary.” Some health or coordination information may need to be shared for consistent support. Conversely, an apparently ordinary phrase or promise may belong only to one relationship history.

Cross-topic events were not forced apart

A single event can connect a project decision, a purchase, and a deadline. Generation should not predict every future retrieval angle and split one coherent story into fragments. Multiple cluster membership was reserved for the index layer.

3. How Cards were generated

One model pass, without pre-compression

raw conversation turns + agent operating context + frozen Card headlines as prior context -> reasoning model -> one or more narrative event Cards

A proposed two-model pipeline first compressed the transcript into atomic facts and then asked a stronger model to write Cards. Experiments showed that the intermediate representation discarded causal and tonal information. Bounded windows made the additional layer unnecessary.

Activity and time both gated generation

Generation did not run on a fixed clock or bind itself to one session. It required both enough new turns and enough elapsed time since the previous run. New sessions also had a small minimum-turn gate, avoiding a paid call for accidental or extremely short exchanges. Existing sessions could update from fewer turns because a small continuation might complete an already meaningful event.

Freeze/refeed: rewrite the newest Card

existing Cards: [A] [B] [C: mutable tail] + new turns freeze: [A] [B] re-feed: end of B + C's turns + new turns result: replace C with one or more revised Cards

Appending at a mechanical boundary produced half-events and duplicate summaries. Re-feeding the tail let the model decide whether the new material continued the last event or opened a new one. Stable history remained frozen, bounding both cost and rewrite risk.

Initial long sessions used the same mechanism

A long first session was processed in growing windows. After each successful pass, all but the newest Card became stable. The next window began from the previous boundary and included frozen headlines as a compact account of what had already been recorded.

4. Four time scales

profile = active directory of important themes recent = short FIFO continuity view event Cards = expandable narrative records clusters = long-horizon thematic organization

Profile as a traceable directory

The proposal rejected a free-standing model-written “profile of the user.” Such prose was easy to generalize beyond its evidence. Instead, the intended profile would compose selected Card headlines, leaving every sentence traceable to an event record.

Recurring background versus episodes

Long-lived background could not be selected reliably from one Card. The proposed promotion signal combined week span, coverage across weeks, and recency. A concentrated episode would remain recent; a pattern recurring across many weeks could become standing context. One-time durable declarations were recognized as a separate class that frequency alone could not discover.

Recent view

A deterministic recent file listed visible Card headlines from a configurable lookback window. It intentionally omitted Card bodies. The agent received immediate continuity without loading the archive or exposing private prose through a broad summary.

Cards and clusters

Cards remained the expandable source of narrative truth. Clusters were an entry point into older material: a summary could lead to a dated Card timeline and then to one full Card. Old events were not deleted merely because they stopped appearing in the active directory.

5. Retrieval and clustering experiments

Topic and time were separate axes

Vertical retrieval followed one storyline through a cluster timeline. Horizontal retrieval sliced all events by time. The design did not need two copies of memory; it needed timestamps to survive every projection. Time ordered and filtered events but did not decide topical similarity.

Initial retrieval stack

  1. Search Card text and tags with FTS.
  2. Group hits under cluster summaries.
  3. Expand a cluster into a dated Card timeline.
  4. Open a Card for its visible narrative and source detail.

LIKE and source-turn search remained fallbacks. Clustering was an organization mechanism, never the only way back to memory.

Embedding plus entity evidence

Semantic similarity handled paraphrase and broad topic resemblance. Weighted entity overlap rescued long-running lines whose vocabulary had shifted. Rare concrete entities carried more weight than universal names or generic emotional terms.

Why mean-centering was mandatory

Raw Card embeddings occupied a narrow, high-cosine region because the corpus shared language and background context. In one experiment, raw pairwise cosine values ranged roughly from 0.65 to 0.98 with a median near 0.80. After subtracting the corpus mean, values spread across roughly -0.33 to 0.89. The precise numbers were model-specific; the lesson was that a threshold has no meaning outside the scale that produced it.

Co-occurrence instead of a hand-written synonym dictionary

Exact tags fragmented when the model used alternate names. Generic dictionaries missed local domain terms, while embeddings of isolated tags confused synonymy with loose relatedness. The experiment used first-order co-occurrence and similarity between co-occurrence profiles so the corpus could reveal which terms behaved alike.

Centroid plus tail

An early assignment rule compared a new Card with both a cluster centroid and the average of its most recent Cards. The tail sometimes followed a fast-moving storyline, but mostly helped only within dense conversation bursts. It also created the worst accidental bridges. Entity evidence handled cross-session continuity more safely, so tail matching was retired.

Relative thresholds and the magnet-cluster problem

Absolute cosine thresholds failed as the corpus became denser. Replacing them with a z-score relative to each Card's similarity background was more portable across dense and sparse regions, but did not solve the underlying representation problem.

Finding

The “magnet” was not primarily centroid drift. It was a single-link chain: every neighboring pair could be plausibly similar while the two ends of the chain were unrelated. Smarter edge definitions followed by connected components recreated the same transitive failure. Resistance to chains came from aggregate comparison, not from declaring a cleverer pairwise edge.

Local recursive refinement

Large groups were recursively reconsidered with local background statistics. This produced a useful multi-resolution intuition—zoom into heterogeneous regions—but residual-space experiments often split chains arbitrarily. The process exposed a ceiling: continuous distances between Cards were being asked to supply discrete structure they did not naturally contain.

6. Viewer-specific privacy

Each Card recorded the workspace that produced it. The owner could read shared and private fields; another viewer could read the Card only when it had shared text, and then saw only that shared text. The original design embedded full Card context for indexing and filtered at query/display time.

Why not ask generation to write self-contained shared prose?

A shared conclusion may depend on a private cause. Asking the model to hide the cause while making the conclusion read smoothly encouraged vague invention. The design kept the original causal context in the Card and placed deterministic filtering at the read boundary instead.

The threat model was accidental disclosure inside one trusted local user account, not hostile tenant isolation. Later versions strengthened the tool boundary with shared visibility predicates and filtered database copies.

7. Rejected paths

Fully local low-tier extraction

Small local models frequently reconstructed multilingual tokens incorrectly, copied examples, and over-classified ordinary text as memorable. The task had a real reasoning floor; cost reductions had to come from call frequency and payload size instead.

Instruction-style extraction

Mechanical extraction preserved facts but lost salience and causal texture. Operating-context generation replaced it.

Keyword or atomic-sentence Cards

They embedded poorly and forced later readers to reconstruct missing context. Natural-language event prose remained canonical.

Pure embedding clustering

It handled local semantic similarity but failed to reconnect long arcs. Entity evidence was added, then later moved into the graph.

Global cosine thresholds

Both raw and mean-centered versions were brittle under uneven density. A threshold that protected one topic region fragmented another.

Local edge rules plus connected components

Mutual-kNN and local z-score edges still collapsed through single-link transitivity.

Generate standing facts while writing each Card

One Card lacked the cross-session view needed to distinguish an episode from a durable pattern. Promotion belonged in an aggregation layer.

Knowledge graph as memory storage

Entity relations were useful for indexing, but triples could not preserve the narrative texture or express Card-level visibility cleanly.
